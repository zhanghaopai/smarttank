# 项目结构与架构

## 目录职责

```text
smarttank/
├── src/
│   ├── main.cpp                # 应用启动、启动检查和截图入口
│   ├── core/                   # 工程数据、修订及结果有效性
│   │   └── Project.h/.cpp
│   ├── geometry/               # OCCT 几何生成，无 Qt 窗口依赖
│   │   ├── EnvelopeGeometry.h/.cpp  # 参数到外形预览
│   │   └── InstalledGeometry.h/.cpp # 安装曲面到板件形状
│   ├── view/                   # 原生查看器、显示状态及鼠标交互
│   │   ├── OcctView.h/.cpp      # 窗口生命周期、输入及截图
│   │   └── OcctViewPresentation.cpp # 缓存显示、显隐及高亮
│   └── ui/                     # 主窗口、参数输入和操作编排
│       ├── MainWindow.h/.cpp       # 初始化、输入应用及工程操作
│       ├── MainWindowLayout.cpp   # 三列工作区和控件构造
│       ├── MainWindowActions.cpp  # 菜单、快捷键及工具栏
│       └── ParameterEditor.h/.cpp # 可空正数输入、校验及字段错误
├── tests/                      # 工程状态、工作区及几何回归检查
├── devops/                     # 一键构建、测试和启动脚本
├── docs/                       # 需求、环境、操作及架构说明
├── openspec/                   # 变更提案、规格与任务
├── .agents/skills/             # 项目技能
├── .deps/                      # 本地依赖（不入库）
└── build/                      # 构建产物（不入库）
```

## 构建边界

箭头表示左侧目标依赖右侧目标：

```text
smarttank → smarttank_ui → smarttank_view → smarttank_geometry → smarttank_core
                 Qt Widgets ↗       OCCT ↗
```

- `smarttank_core` 只依赖 C++ 标准库，保存工程真实数据，管理修订及结果失效。
- `smarttank_geometry` 依赖 core 和 OCCT 建模库，生成形状并验证几何，不创建窗口，不修改工程。
- `smarttank_view` 依赖 geometry、Qt Widgets 和 OCCT 显示库，管理相机、高亮、显隐和截图。
- `smarttank_ui` 依赖 view，读取和修改工程参数，协调预览和操作反馈。
- `smarttank` 负责启动应用。测试依赖 Qt Test 仅在 `BUILD_TESTING=ON` 时查找。

头文件公开使用的 OCCT 类型通过 geometry 目标传播包含目录。Qt 自动元对象处理只对包含 `Q_OBJECT` 的目标启用。

## 新代码放置规则

工程数据和结果状态放入 core；OCCT 形状转换放入 geometry；显示交互放入 view；表单和窗口操作放入 ui。下层模块不引用上层窗口或控件。

外形预览不写入 `Project::plates()`。安装曲面与制造轮廓保持独立；制造导出不能从显示网格或预览外形反推数据。

排板、计算、持久化和导出目前尚未实现。实现对应功能时再依据规格建立模块，不预建空目录或通用服务层。

## 本次架构审查

| 位置 | 问题 | 严重性 | 整理方式及影响 |
| --- | --- | --- | --- |
| `CMakeLists.txt` 原 `smarttank_ui` 目标 | 窗口、建模和显示共用一个构建目标，无法独立复用建模层 | 中 | 拆为 geometry、view、ui，明确依赖方向 |
| `src/view/OcctView.cpp` 原 `makeInstalledShape` | 查看器同时负责曲面建模、边界验证与显示 | 中 | 函数原样迁移到 `geometry/InstalledGeometry`，可脱离 QWidget 调用 |
| 原 `src/view/EnvelopeGeometry.*` | 无窗口依赖的建模代码位于查看器目录 | 低 | 迁入 geometry，统一几何代码归属 |
| `CMakeLists.txt` 的 Qt Test 查找与全局 AUTOMOC | 非测试构建仍要求测试库，纯数据目标也启用 Qt 处理 | 低 | 条件查找 Qt Test，按目标启用 AUTOMOC |

## 可读性审查与整理

| 位置 | 问题 | 严重性 | 处理及预期影响 |
| --- | --- | --- | --- |
| `MainWindow.cpp` 构造函数 | 约 220 行同时构造布局、菜单并连接事件 | 中 | 拆成工作区、操作入口、事件连接三个明确步骤；布局和菜单分别维护 |
| `MainWindow.cpp::selectPart` | 字段创建、解析、校验、工程更新混在循环和长 lambda 内 | 中 | 分为选择组件、创建字段、应用输入三个函数，便于定位输入问题 |
| `OcctView.h::objects_` 及原 `parts_` | 两个映射依靠相同 ID 维护显示对象及所属组件 | 中 | 用 `DisplayedObject` 同时保存组件和显示对象，消除跨映射查找及同步要求 |
| `OcctView.cpp::highlightPart` | 多层条件表达式混合组件识别和颜色选择 | 低 | 提取 `componentColor`，显式表达选中状态和组件颜色 |
| `OcctView.cpp::showEvent` | 两个异常分支重复清理和失败通知 | 低 | 提取统一失败处理函数，保留异常类型和原有清理顺序 |
| `Project.cpp` | 短名称、复合单行语句不利于阅读验证路径 | 低 | 使用明确的索引、板件 ID、制造编号和覆盖状态名称，展开失败分支 |

菜单和工具栏通过局部 `WorkspaceActions` 共享 QAction，不依赖字符串查找。三个 UI 实现文件仍属于同一个主窗口类；这是按代码职责拆分，没有增加额外控制器或服务层。增加真实排板、计算或保存流程时，应将业务流程放入对应模块。现有源码中未发现循环包含或循环目标依赖。

## 职责与分支结构复审

| 位置 | 发现 | 严重性 | 已实施的重构及影响 |
| --- | --- | --- | --- |
| `MainWindow.cpp::addParameterField` 及原 `applyParameterInput` | 主窗口依赖输入框、错误标签和数值解析细节 | 中 | 提取独立 `ParameterEditor`，负责区域格式、完整精度、可空正数验证和错误展示；主窗口接收合法值并更新工程 |
| `MainWindow.cpp::newProject`、`loadPreviewExample`、`closeEvent` | 三个确认分支重复，且新建及示例替换遗漏尚未应用输入 | 中 | 共用 `hasUnsavedChanges` 和 `confirmDiscardChanges`；覆盖未保存工程及未应用输入，取消不会丢弃字段 |
| `Project.cpp::acceptLayout`、`acceptChecks` | 校验细节、失败原因和结果状态提交交织 | 中 | 用无状态校验函数返回失败原因；公开方法按修订检查、校验、提交依次执行，保留原校验顺序和结果失效语义 |
| `Project.cpp::markInputsChanged` | 排板和校核重复执行同一失效分支 | 低 | 共用 `markStale`，只把 Current 转为 Stale，保留其他状态 |
| `OcctView.cpp` | 原生窗口生命周期与显示缓存管理混排 | 低 | 显示方法移至 `OcctViewPresentation.cpp`，仍使用同一类和同一份缓存，不增加额外状态同步 |
| 原 `replaceObjects(..., bool)` | 调用处的 true/false 无法表达显示意图 | 低 | 改用 `PresentationKind::Plates/Envelope`，缓存显示函数命名为 `displayCachedObjects` |
| `MainWindow.cpp::updatePreview` | 正常路径嵌套，两个异常分支重复错误处理 | 低 | 缺少尺寸时提前返回，共用 `showPreviewFailure`，使正常预览路径保持平直 |

此次保留原有三列布局、对象名称、键盘操作、精度保持和原生画布释放时序。没有引入通用工厂、策略注册表或未使用的接口；固定三部位的 switch 保持显式列举。结果校验仍属于 core，输入控件不持有 Project，UI 不接管几何建模。

## 验证

在项目根目录运行：

```powershell
cmake --preset windows-preview
cmake --build --preset preview
ctest --preset preview
```

默认自动测试使用 offscreen 平台；原生 Windows 三维渲染与鼠标交互需额外运行原生工作区测试。
