# Design

## Context

见 `proposal.md` 的动机及四份能力规格。规划开始时仓库无应用源码、构建配置和测试基础；实施阶段已建立基础工程，见下述实施记录。已读取 `docs/02-MVP需求范围.md`；`docs/mvp需求范围.md` 不存在。

本设计只确定足以承接已确认行为的结构，不替用户选择计算依据、制造方法或第三方依赖。下文标记“已确认”的内容来自探索结论；“建议”仅为此次提案的实现方案。

## Goals / Non-Goals

**Goals:**
- 使工程、排板、计算与输出保持一致，显示细节不影响制造尺寸。
- 以简单模块和固定规则完成闭环，分别验证持久化、几何、计算及导出。
- 在架构中显式表示未确定依据和失效结果，支持先实现不依赖这些依据的部分。

**Non-Goals:**
- 不构建通用 CAD 编辑器、CAD 双向同步、排板优化器或复杂插件体系。
- 不以三维网格或投影代替下料计算，不增加未确认罐型及校核范围。
- 不在工程依据确认前选择或实现 API 650 条款公式。

## Decisions

### 1. 离线 C++ / Qt 桌面应用（已确认）

所有核心操作在本地 Windows 完成，不引入授权服务器或网络前置依赖。Qt 提供桌面交互；UI 路线已确认采用 Qt Widgets，构建工具采用 CMake，编译器采用 MSVC。开发环境已配置 Qt 6.8.3、MSVC 14.40.33807 和 CMake 3.29.2，环境记录见 `docs/03-开发环境.md`。

替代方案：在线服务或另一技术栈。它们不符合已确认的离线环境和 C++ / Qt 约束。

### 2. 共同工程与板件数据驱动两种表达（已确认）

保存工程参数、排板定义及板件身份；每块板包含所属部位、制造编号、边界定义、材料和厚度等对应信息。三维表示其安装位置及曲面形态，二维表达平面排板或展开制造轮廓。

```text
Engineering parameters + confirmed rules
                    |
                    v
         Layout + plate definitions
                    |
                    +--> 3D preview
                    +--> 2D manufacturing geometry --> DXF
                    +--> Plate schedule -----------> CSV

Engineering parameters + calculation basis
                    |
                    v
             Check results ------------------------> Report
```

替代方案：以三维显示网格为主数据，再投影得到制造轮廓。该方案无法保持显示精度与下料精度独立，且投影不等于展开，故不采用。

建议为生成结果记录设计修订或输入指纹，防止旧数据混入当前输出。ID 在同一设计、重绘和保存重开时稳定；拓扑改变后的继承及编号重分配策略待确认，不承诺一块已被拆分的板仍永久对应单一旧 ID。

### 3. 参数驱动固定排板（已确认）

用户只能修改参数，生成板件及接缝不可直接编辑。固定规则重复执行应给出一致结果。不做材料利用率优化。

替代方案：手动排板或自动生成后人工调整。均超出当前交互范围。

建议将规则校验、排板生成与输出分开。具体参数集合、板材规格输入、拼接策略、余量及尺寸参考面仍待确认；不能把对这些内容的举例当作要求。

### 4. 各部位独立生成制造几何（已确认）

罐底采用平面排板，罐壁采用圆柱面展开，自支撑锥顶采用锥面展开；装配视图需要时可使用几何投影，但制造轮廓不从截图或显示网格提取。

替代方案：所有部位使用同一个投影算法。这不能表达所需的下料尺寸，故不采用。

建议制造几何使用独立于渲染的轮廓与尺寸数据，由 DXF 导出读取；精确几何实现库、容差和曲线表达待确认。球顶的成形下料问题不在本变更中解决。

### 5. 计算依据与结果范围显式化（已确认）

只实现三部位已确认的基础厚度规则，材料支持一种。标准版次、材料性能、输入工况、公式与适用边界未确认前，不提供声称有效的计算结论。报告注明已覆盖及未覆盖内容。

替代方案：先采用猜测公式和材料默认值。会把待定依据误表达为真实计算能力，故不采用。

建议结果记录输入、依据、通过/不通过/不适用或缺失状态；参数变化后标记需重新计算。基础 UI 和数据模型可先完成，具体计算实现等待相关确认任务。

### 6. 单向输出与简单模板（已确认）

DXF 输出排板图、展开及板件下料轮廓、尺寸和编号；CSV 输出明细，报告使用固定模板。导出的 CAD 不作为工程输入。

替代方案：DWG 必须支持、可编辑图纸回导或复杂模板编辑器。均不纳入 MVP。

建议输出统一读取一个有效当前设计状态；各类输出的前置条件分别校验，不要求仅为导出有效排板而强制执行所有计算。DXF 版本、单位与 CAD 验收环境，以及 CSV 列定义和报告文件格式待确认。

### 7. 简单模块边界（本提案建议，非此前已确认选型）

采用 UI、工程数据与持久化、排板及制造几何、三维表达、计算、导出这些职责边界，优先在一个本地应用中实现。计算及几何核心尽量不依赖界面控件，便于用参考案例检验。

替代方案：先引入服务、插件系统或复杂运行时扩展。对当前闭环没有必要。本提案不指定具体类名、数据库、JSON 编码或 DXF 实现库；三维预览采用下述已确认的 OCCT 选型。

### 8. OCCT 三维预览（已确认）

三维预览采用 Open CASCADE Technology（OCCT），从共同工程及板件数据生成显示表达，支持储罐与板件划分展示及旋转、缩放。显示对象通过板件 ID 与共同板件数据关联，不作为工程或制造尺寸的主数据。

OCCT 三维预览选型不替代罐底平面排板、罐壁圆柱面展开或锥顶锥面展开的制造规则；改变显示精度或观察方向不影响下料轮廓与尺寸。Qt Widgets、CMake 和 MSVC 已确认；开发环境已配置 OCCT 8.0.1，采用 vcpkg `x64-windows` 动态库并通过 CMake 接入，Qt Widgets 与 OCCT 联合编译、链接和运行验证通过。查看器已通过 Windows 原生窗口嵌入 QWidget，真实排板数据的集成验收仍待完成，不增加精确拾取、剖切或 CAD 导入等验收要求。

## Implementation Notes

已建立 CMake/MSVC 应用、Qt Widgets 工作区、纯 C++ 共同板件数据和设计修订状态，以及嵌入 QWidget 的 OCCT 查看器。安装曲面使用解析曲面与参数域边界，二维制造轮廓独立存储；显示对象通过板件 ID 映射。

任务 1.6 的 Qt/OCCT 工具链部分已就绪，因此完成不依赖制造几何/DXF 选型的应用工程与基础工作区。数据模型仅承载外部生成器提供的板件 ID，没有实现待确认的拓扑继承或编号策略；没有实现 `.st` 持久化。参数面板先提供基础尺寸且不预填数值，完整排板输入集合仍依赖任务 1.3。

用户已要求优先实现三维视图。应用从共同工程参数生成罐底圆盘、罐壁圆柱侧面和锥顶侧面的外形预览；直径与高度齐全时显示前两部位，锥顶升高有值时显示罐顶。预览使用零厚度组件曲面，不计入板件数据，不计算制造尺寸，不将排板或校核结果标为有效。组件显隐、高亮、旋转缩放及常用视角均仅改变显示。新工程参数仍为空，“载入示例尺寸”仅在用户操作时设置外形尺寸。

当前没有真实排板生成器，应用不生成测试板件；合成板件仅用于验证显示及制造数据独立性。OCCT 板件预览生成器已具备三类曲面显示、边界、旋转缩放和 ID 映射能力，但任务 4.2 保留未完成，等待真实排板数据的集成验收；任务 4.3 的外形更新已实现，完整排板联动同样等待排板规则。

当前查看器使用 4 倍 MSAA 与更细的显示离散精度，外形预览不绘制周期曲面的参数接缝，避免将显示接缝表达为制造板件接缝。清空直径或高度会撤下外形，清空锥顶升高仅撤下罐顶；空值提交行为已修复并通过回归测试。

Release 构建、3/3 自动测试通过；两项 Windows 原生图形测试覆盖板件显示与导航，以及工作区外形随尺寸更新、组件显隐、清空输入和预览不生成制造结果。完整应用原生启动及截图生成通过单独验证。最新三维构建位于 `build/windows-preview/Release/smarttank.exe`，`tools/run.ps1` 选择最近编译的应用；`tools/run.ps1 -Example` 显式打开示例尺寸。参考 `docs/03-开发环境.md` 与 `docs/04-当前版本操作说明.md`。

## Risks / Trade-offs

- [基础校核范围尚未具体定义] → 先确认规则矩阵、输入与参考结果，相关公式实现及验收以此为前置条件。
- [制造几何正确不代表下料规则正确] → 明确尺寸参考面、接缝及余量，使用经确认的制造案例核对轮廓和尺寸。
- [改变排板拓扑影响板件身份] → 定义编号及身份更新规则，确保同一当前设计的三维、DXF 和 CSV 一致。
- [缓存表达或计算过期] → 绑定设计状态，修改相关参数后使旧结果失效，不静默导出旧结果。
- [固定排板无法覆盖任意参数] → 明确适用边界和失败提示，不通过自动优化隐藏不适用情况。
- [DXF 在不同 CAD 环境呈现差异] → 确认目标版本和验收环境，再检查曲线、单位、文字和尺寸的实际显示。

## Migration Plan

没有既有应用数据或接口需要迁移。实施按任务清单先建立工程数据与基础流程，再接入经确认的计算、制造规则和输出。`.st` 内部结构与格式版本策略在持久化实现前确认。

交付前以一个确认适用的案例执行端到端闭环，并在断网 Windows 上检查运行。回退策略为保留原工程文件，禁止失败保存或导出被当作成功；具体文件写入策略由实现阶段设计。

## Pending Confirmations / Implementation Gates

这些是用户明确要求保留的待定项，不是本设计擅自给出的默认决定。规划产物可以完成；受影响实现和验收必须在相应确认后继续。

| 待确认事项 | 阻塞的工作 |
|---|---|
| API 650 版次、增补 | 规则条款引用、计算实现、报告计算依据 |
| 单一材料牌号及性能数据 | 材料配置、厚度校核、正式制造输出 |
| 三部位基础厚度校核项目、输入工况、公式、适用条件及参考案例 | 计算模块实现及数值验收 |
| 固定排板规则、必要参数、板材输入及适用范围 | 自动排板实现及验收 |
| 尺寸参考面、接缝、制造余量、展开规则、容差及参考案例 | 下料轮廓和制造尺寸实现及验收 |
| 板件拓扑变化后的 ID/制造编号策略 | 拓扑更新及保存重开一致性验收 |
| 真实排板数据与查看器的集成验收、制造几何/DXF 依赖（Qt 6.8.3、OCCT 8.0.1 及 QWidget 查看器基础集成已完成） | 板件预览联动、制造几何与输出集成 |

| DXF 版本、单位、图层/标注最小约定与验收 CAD 环境 | DXF 实现及兼容验收 |
| CSV 最小字段与编码、固定报告模板及文件格式 | 明细与报告实现及输出验收 |

后续确认应限制在既定 MVP 内，不借此加入新罐型、优化、专项校核或 CAD 回导。
